# CLAUDE.md — Инструкции для ИИ-агентов по ведению knowledge-wiki

Этот файл содержит ключевые команды и правила, обязательные для выполнения любым ИИ-агентом (Antigravity, Claude Code и др.) при работе с базой знаний `knowledge-wiki`.

## Команды автоматизации

- **Проверка базы знаний (линтер):**
  `python scripts/wiki_lint.py` — запускает проверки целостности YAML, тегов и ссылок перед коммитом.
- **Обновление статистики:**
  `python scripts/wiki_tool.py --update-stats` — автоматически рассчитывает статистику базы знаний и обновляет её в `INDEX.md`. **Обязательно запускать перед коммитом!**
- **Проверка новых файлов во входящих:**
  `python scripts/wiki_tool.py --check-inbox` — сканирует папку `inbox/` на наличие новых материалов.
- **Сводка по базе знаний:**
  `python scripts/wiki_tool.py` — показывает общую статистику и статус папки `inbox/`.

## Karpathy Ingestion Workflow (Процесс импорта)

При появлении файлов в `inbox/` или при импорте из бэклога `inbox/sources_to_ingest.md`, ИИ-агент обязан строго следовать процедуре:

1. **Создание карточки источника в `sources/`:**
   - Создать файл вида `sources/название-источника.md`.
   - **КРИТИЧЕСКОЕ ТРЕБОВАНИЕ:** Скопировать и сохранить **ПОЛНЫЙ ТЕКСТ (full text)** оригинального материала (судебного акта, письма ведомства, статьи). **Запрещено урезать, сокращать или превращать материалы в краткие конспекты!** Полный текст жизненно необходим для точности юридического поиска и последующей работы.
2. **Синтез информации в темы `topics/`:**
   - Найти подходящие концептуальные статьи в `topics/<домен>/` или создать новую (в рамках лимита вложенности).
   - Интегрировать ключевые выводы и цитаты из источника в логические разделы тем.
   - Ссылаться на источник через стандартные markdown-ссылки от корня репозитория: `[Текст](sources/название-источника.md)`.
3. **Обновление `CHANGELOG.md`:**
   - Записать дату, перечень добавленных/изменённых файлов и краткое резюме внесённых знаний.
4. **Запуск автоматизации перед коммитом:**
   - Запустить `python scripts/wiki_tool.py --update-stats` для обновления `INDEX.md`.
   - Запустить `python scripts/wiki_lint.py` для подтверждения целостности (ошибок должно быть **0**).

## Стандарты качества

### 1. Формат ссылок (Docsify)
- Ссылки в текстах должны строиться строго от корня репозитория: `[Текст](topics/gradostroitelstvo/gpzu.md)` или `[Источник](sources/название-источника.md)`.
- **Запрещено** использовать двойные скобки Obsidian `[[PageName]]`.
- **Запрещено** использовать префиксы выхода за рамки корня (например, `../topics/...` или `../../sources/...`).
- В YAML-поле `related_topics` пути указываются как простые строки без markdown-разметки:
  ```yaml
  related_topics:
    - topics/gradostroitelstvo/gpzu.md
  ```

### 2. Управление тегами (Gravity Tags)
- Все теги, используемые в YAML-шапках файлов, должны быть строго зарегистрированы в [tags-registry.md](tags-registry.md).
- Применяйте концепцию **Gravity Tags**: стремитесь приводить узкоспециализированные теги (статьи законов, мелкие детали) к более общим зарегистрированным понятиям среднего уровня (например, использовать `ГрК` вместо `ГрК-55.8`, `саморегулирование` вместо `НК-комиссия`).

### 3. Ограничение вложенности
- Темы в `topics/` могут лежать на глубине не более 2 уровней: `topics/<домен>/<тема>.md`. Никаких вложенных папок внутри доменов.

### 4. Обязательные YAML-поля
Каждый файл в `sources/` и `topics/` обязан содержать YAML-шапку с полями:
- `title` (официальное название)
- `type` (`источник`, `тема`, `судебный акт`, `письмо органа`)
- `status` (`verified` или `draft`)
- `date_added` (YYYY-MM-DD)
- `tags` (список тегов)
