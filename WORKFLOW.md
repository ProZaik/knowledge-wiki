# Workflow — Как добавлять знания

## Сценарий 1: Быстрая заметка

Ты кидаешь текст или идею → AI создаёт файл в `topics/<тема>/<название>.md`

## Сценарий 2: Источник с материалом

Ты кидаешь ссылку или текст из источника → AI:
1. Создаёт карточку источника в `sources/`
2. Создаёт заметку в `topics/`
3. Связывает их между собой

## Сценарий 3: Необработанное

Если нужно просто сохранить «на потом» → файл идёт в `inbox/` со статусом `draft`

## Сценарий 4: Обновление существующей заметки

Ты говоришь «добавь это к теме X» → AI находит файл и обновляет его

---

## Структура папок

```
knowledge-wiki/
├── topics/
│   ├── <тема-1>/
│   │   ├── _index.md       ← обзор темы
│   │   └── <заметка>.md
│   └── <тема-2>/
├── sources/
│   └── <источник>.md
├── inbox/
│   └── <черновик>.md
└── templates/
    ├── note.md
    ├── source.md
    └── topic-index.md
```

## Статусы заметок

- `draft` — необработанное, сырой материал
- `verified` — проверено и структурировано
- `needs-review` — требует проверки (конфликт, устаревание)
- `archived` — устарело, но сохраняется

## Правила обновления существующих заметок

### Материал дополняет существующий

Признаки: новый источник раскрывает тему глубже, добавляет примеры, уточняет детали — но не противоречит.

Действия AI:
1. Найти связанный файл в `topics/` или `sources/`
2. Добавить новые данные в соответствующий раздел файла
3. Обновить `date_updated` в YAML-шапке
4. Добавить в конец файла сноску:
   ```
   > Обновлено: ГГГГ-ММ-ДД — [что добавлено и на основании какого источника]
   ```
5. Создать карточку нового источника в `sources/` (если источник новый)

### Материал конфликтует с существующим

Признаки: новый источник даёт другую позицию, другой вывод суда по аналогичному делу, или противоречит ранее зафиксированному правилу.

Действия AI:
1. **Не перезаписывать молча** — зафиксировать конфликт явно
2. Добавить раздел `## ⚠️ Противоречия` в существующий файл
3. Прописать структуру конфликта:
   ```markdown
   ## ⚠️ Противоречия

   | Источник | Позиция |
   |---|---|
   | [источник A](ссылка) | ... |
   | [источник B](ссылка) | ... |

   **Оценка:** [какая позиция актуальнее и почему — со ссылкой на дату, инстанцию, норму]
   ```
4. Изменить статус файла на `needs-review`
5. Добавить в YAML-шапку: `conflict_with: [путь к конфликтующему файлу]`

### Неясно — дополнение или конфликт

Действия AI:
1. Сохранить материал в `inbox/` со статусом `draft`
2. Добавить в YAML-шапку:
   ```yaml
   conflict_with: topics/<тема>/<файл>.md
   note: "Требует сравнения — возможен конфликт с существующей позицией"
   ```
3. Сообщить пользователю: что именно вызвало сомнение и с каким файлом

## Правила для судебной практики

Судебные акты — особый случай: два дела с разными выводами не обязательно конфликт, это **расхождение практики**.

- Если вывод суда **совпадает** с зафиксированным → добавить как подтверждающий прецедент
- Если вывод **расходится** → добавить как противоположную позицию с указанием округа, инстанции и даты
- Если **вышестоящий суд** пересматривает позицию нижестоящего → обновить основной вывод, старый перенести в раздел `## История позиции`
- Постановления Пленума ВС РФ и Президиума ВАС РФ имеют **приоритет** над позициями нижестоящих судов

## YAML-шапка файла (обязательные поля)

```yaml
---
title: "..."
type: заметка | судебный акт | источник | тема
status: draft | verified | needs-review | archived
date_added: ГГГГ-ММ-ДД
date_updated: ГГГГ-ММ-ДД        # заполнять при каждом обновлении
tags: [тег1, тег2]
related_topics:
  - topics/...
conflict_with:                   # заполнять при конфликте
  - sources/...
---
```
